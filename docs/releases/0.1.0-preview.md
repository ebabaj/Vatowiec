bez `dotnet run`, z katalogu roboczego poza repozytorium. Test ustawia także
nieistniejący DOTNET_ROOT i wyłącza multilevel lookup; komputer testujący nadal
ma SDK/runtime, więc nie zastępuje to próby na czystym Windows.

- edycję URL i kontakt z prawdziwym `https://localhost:7243` przy standardowej
  walidacji TLS; celowo nieistniejący, unikalny login otrzymał odmowę Identity;
- odrzucenie zwykłego HTTP przed wysłaniem danych;
- rzeczywiste odrzucenie niezaufanego certyfikatu odizolowanego lokalnego
  serwera TLS i czytelny komunikat (bez instalowania CA/certyfikatu w Windows);
- komunikat o niedostępnym API;
- zachowanie istniejącego pliku preferencji bajt w bajt po zamknięciu klienta.

Wynik: `TestResults/release-preview-lifecycle.txt`. Nie resetowano haseł,
kont, uprawnień ani baz; nie uruchamiano destrukcyjnych testów SQL, migracji
ani zapytań do integracji produkcyjnych. Nie zmieniano sieci/zapory/API config.

## Instalator i pełny cykl instalacji

Po zgodzie użytkownika zainstalowano per-user **Inno Setup 6.7.3**, przez
`winget install --id JRSoftware.InnoSetup --exact --source winget --scope user`.
Winget pobrał plik z oficjalnego wydania `jrsoftware/issrc` na GitHub i potwierdził
`Successfully verified installer hash`. Kompilacja `.iss` przez
`tools/release/build-release.ps1`: **powodzenie**.
Log: `TestResults/release-installer-build.txt`.

`tools/release/Test-Release.ps1 -RunInstaller`: **41 potwierdzonych kontroli**,
bez błędów, na bieżącym koncie Windows, które przed próbą nie miało instalacji
ani skrótów z tym AppId. Nie tworzono dodatkowego konta Windows. Test zakończył
się odinstalowaniem swojej instalacji i usunięciem wyłącznie własnego,
unikalnego fikcyjnego poświadczenia. Nie enumerował istniejących haseł.

Potwierdzono rzeczywiście:

- instalację do `%LOCALAPPDATA%\Programs\VATowiec`, `User privileges: None`,
  `Administrative install mode: No`, klucz odinstalowania w HKCU;
- wersję `0.1.0-preview` na liście aplikacji Windows;
- skrót Start i jawnie zamówiony skrót pulpitu, oba z właściwym celem;
- uruchomienie zainstalowanego i ponownie zainstalowanego EXE, ekran logowania,
  kontakt z rzeczywistym API HTTPS, zmianę URL, odrzucenie HTTP i niezaufanego
  certyfikatu oraz komunikat o niedostępnym serwerze;
- reinstalację przy **uruchomionym kliencie**: Restart Manager wykrył
  `Vatowiec.Desktop` i zamknął proces, instalator zakończył się kodem 0;
- brak zmian bajtów istniejącego pliku preferencji i zachowanie fikcyjnego wpisu
  Credential Manager po reinstalacji oraz po odinstalowaniu;
- usunięcie programu, skrótów i wpisu aplikacji przez uninstaller, bez restartu
  Windows i bez usuwania preferencji.

Logi: `TestResults/release-preview-lifecycle.txt`, `release-install.txt`,
`release-reinstall.txt`, `release-uninstall.txt`.
Osobno otwarto widoczny kreator: polski interfejs i domyślna ścieżka instalacji
były poprawne. Późniejsza instalacja z tego kreatora nie jest automatycznie
usuwana przez testy; skrypt odmawia ingerencji w zastaną instalację.

## Granice weryfikacji

Nie wykonano próby na drugim fizycznym komputerze ani czystym Windows 10/11.
Nie skonfigurowano rzeczywistego LAN/VPN; osobna instrukcja opisuje wymagania.
Nie symulowano niezapisanej edycji biznesowej podczas aktualizacji: użytkownik
powinien zapisać pracę przed uruchomieniem instalatora. Nie dodano wymuszonego
zabijania procesu (`CloseApplications=force`) ani ignorowania TLS.
