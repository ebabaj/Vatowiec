# VAT UE — przegląd źródeł urzędowych 23.10.2026

Wymagania ORG-005/007; wdrożenie ADR-027. Analiza dotyczy tylko VatEuId,
z zachowaniem krajowego PL TaxId. Nie weryfikuje rejestracji, nadania lub statusu VIES.

## Porównanie wszystkich 28 reguł

Wzorzec poniżej dotyczy części po prefiksie; domyślnie źródłem formatu jest Vero.
„Bez zmiany” oznacza brak potwierdzonej rozbieżności, a nie potwierdzenie rejestracji.

| Kraj / prefiks | Dotychczasowy format | Wynik przeglądu | Kontrola od 23.10.2026 |
|---|---|---|---|
| AT | U + 8 cyfr | Bez zmiany | FormatOnly/Unknown |
| BE | 10 cyfr | Zawężenie pierwszej cyfry do 0/1 wg SPF Economie | FormatOnly/Unknown |
| BG | 9 lub 10 cyfr | Bez zmiany | FormatOnly/Unknown |
| HR | 11 cyfr | Format bez zmiany | ISO 7064 MOD 11,10 |
| CY | 8 cyfr + litera | Bez zmiany | FormatOnly/Unknown |
| CZ | 8–10 cyfr | Bez zmiany | FormatOnly/Unknown |
| DK | 8 cyfr | Bez zmiany | FormatOnly/Unknown |
| EE | 9 cyfr | Bez zmiany | FormatOnly/Unknown |
| FI | 8 cyfr | Format bez zmiany | Modulo 11 |
| FR | 2 znaki alfanumeryczne + 9 cyfr | Bez zmiany | FormatOnly/Unknown |
| DE | 9 cyfr | Bez zmiany | FormatOnly/Unknown |
| GR / EL | 9 cyfr | Zachowany EL | FormatOnly/Unknown |
| HU | 8 cyfr | Bez zmiany | FormatOnly/Unknown |

FI: wagi od lewej 7,9,10,5,8,4,2; reszta mod 11 równa 1 oznacza odrzucenie,
0 daje cyfrę 0, pozostałe dają 11 minus reszta. Testujemy obie gałęzie i błędy.
Przykład FI07654321 na stronie o konstrukcji VAT to ilustracja formatu, nie
wzorzec poprawnej sumy: według specyfikacji reszta wynosi 9, oczekiwana cyfra 2.
Test go odrzuca. Z fikcyjnego CSV poprawne sumy mają 1234567-1 i 0456789-9.
Pozostałe ilustracje nie są wzorcami poprawności: dla 2345678-6 oczekiwana cyfra
wynosi 0, a dla 3456789-2 reszta 1 wyklucza numer. Testy odrzucają obie wartości;
nie dostosowujemy algorytmu urzędu do błędnych przykładów ilustracyjnych.

HR: dziesięć cyfr przetwarzamy iteracyjnie według opublikowanego MOD 11,10;
ostatnią porównujemy z wyliczonym wynikiem. Wzorce urzędowe: 69435151530
(REGOS, szczegółowa tabela obliczeń) oraz 11111111119 (Porezna). Nie sprawdzamy
ich w usługach ani nie przypisujemy do żadnej osoby/firmy.

Dla pozostałych krajów nie znaleziono w wykorzystanym, zweryfikowanym zestawie
kompletnej specyfikacji wraz z wiarygodnymi wzorcami, więc nie wdrażamy sum
na podstawie wiedzy pamięciowej lub nieurzędowej implementacji. Nie twierdzimy,
że administracje nie publikują takich specyfikacji gdzie indziej.

## Wersje i wdrożenie

29 pierwotnych rekordów pozostaje; tylko ValidTo wersji BE/FI/HR zamyka się
22.10.2026. Trzy nowe rekordy mają wersję 2026-10-23.1 i ValidFrom 23.10.2026.
To okres stosowania polityki w aplikacji, nie data wejścia w życie przepisów.
Nie wyłączamy IsActive starych wersji — muszą działać dla dat historycznych.
PL TaxId, EL, XI i 25 niezmienionych reguł VatEuId pozostają bez modyfikacji.
FormatOnly zwraca Unknown, a Valid oznacza tylko format i sumę, nigdy ważność VIES.

Generowanie SQL nie łączy się z bazą:

```powershell
dotnet build Vatowiec.slnx --no-restore
dotnet ef migrations script 20261022205924_CurrencyPermissions 20261023080602_OfficialVatEuRules --context SystemDbContext --project src/Modules/Core/Infrastructure --no-build --output TestResults/vat-eu-migration.sql
```

Wdrożenie lokalne wykonano jawnie na localhost\SQLEXPRESS (SQL Server 2025
Express, Windows Authentication), po sprawdzeniu znaczników wszystkich trzech
baz i historii: System miał 7 migracji oraz 29 oryginalnych reguł.
Sprawdzono wygenerowane UPDATE trzech ValidTo i INSERT trzech wersji;
bez DROP/DELETE i bez zmiany innych definicji. Wykonano:

```powershell
dotnet run --project tools/database/Vatowiec.DatabaseTools --no-build -- backup-system
dotnet run --project tools/database/Vatowiec.DatabaseTools --no-build -- migrate-system
```

Backup COPY_ONLY/CHECKSUM przeszedł RESTORE VERIFYONLY. Lokalna kopia:
`C:\Program Files\Microsoft SQL Server\MSSQL17.SQLEXPRESS\MSSQL\Backup\Vatowiec_System_before_contractors_d12d8c6ff8be4586a4fa36fcc960bf2c.bak`.
System ma teraz 8 migracji i 32 reguły; A/B nadal po 7 migracji.
Porównanie liczności i SHA256 uporządkowanych rekordów potwierdziło identyczność
wszystkich 40 pozostałych tabel System/A/B bezpośrednio po migracji.
Po testach 39 tabel nadal identycznych; jedyną dodatkową zmianą były zwykłe sesje
logowania w security.UserSessions, jawnie unieważnione przez logout.
Nie usunięto kont, ról, uprawnień ani danych firmowych. Nie tworzono nowych tabel.

Aktualizacja nie uruchamia się przy starcie API. Narzędzie migrate-system
sprawdza także zgodność historii z listą znanych migracji. Downgrade tej migracji
odmawia usuwania historii; odwrócenie decyzji wymaga następnej wersji reguły.

## Weryfikacja i ręczny scenariusz

Wykonano **285/285**, bez błędów i pominięć: 282 bez SQL oraz 3 niedestrukcyjne
SQL/API. Obejmuje to nowe algorytmy, błędne przykłady, wszystkie 28 prefiksów,
granice dat i źródła, brak/nakładanie reguł, zagraniczny TaxId jako Unknown,
zmianę WarningHash, odrzucenie starego potwierdzenia przez API, CSRF i odmowy praw.
Operator odczytuje B, ale nie może w B sprawdzać szkicu ani zapisywać kartoteki;
czytelnik nie ma prawa edycji A/B. Żaden test nie odpytuje rejestrów zewnętrznych.
Kompilacja rozwiązania: 0 błędów i ostrzeżeń. Formatowanie zmienionych plików
przeszło kontrolę. Pełna kontrola formatowania zgłasza zastane błędy WHITESPACE
w niezmienianych ContractorDetailEndpoints.cs, EwibTests.cs i EwibDesktopTests.cs;
nie poprawiano innych modułów przy tej zmianie.

Odtworzenie przebiegu bez czyszczenia danych (zatrzymaj API i desktop przed build):

```powershell
dotnet build Vatowiec.slnx --no-restore
$env:VATOWIEC_PRESERVED_VAT_SQL = '1'
dotnet test Vatowiec.slnx --no-build --filter '(Category!=SqlIntegration)|FullyQualifiedName~OfficialVatRulesSqlTests' --logger 'trx;LogFileName=vat-eu-preserved.trx' --results-directory TestResults
Remove-Item Env:VATOWIEC_PRESERVED_VAT_SQL
$vatChanged = @(git diff --name-only -- '*.cs') + @(git ls-files --others --exclude-standard -- '*.cs')
dotnet format Vatowiec.slnx --verify-no-changes --no-restore --include $vatChanged
```

SQL/API wymaga istniejących profili A/B, aktualnych migracji i lokalnych kont
demonstracyjnych z hasłami w user-secrets `vatowiec-api-development` lub środowisku
(`DemoUsers:Operator:*`, `DemoUsers:Reader:*`). Test nie inicjalizuje/usuwa kont
ani danych. Nie uruchamiaj DatabaseTools test/prepare-tests/initialize: dawne
fixture czyszczą dane. **103 dawne SQL/API wyłączono z bieżącego przebiegu**,
nie raportujemy ich jako zaliczonych. Historyczny wynik 323/323 ADR-026 nie jest
wynikiem tego etapu. Raporty lokalne: `TestResults/vat-eu-preserved.trx`,
`vat-eu-build.log`, `vat-eu-format-changed.log`, `vat-eu-format.log`, `vat-eu-before-data.json`,
`vat-eu-after-data.json`, `vat-eu-final-data.json`.

Bez zmian w ekranach Avalonia: uruchom API i desktop, zaloguj operator.m0 lokalnym
hasłem, wybierz A i otwórz szkic kontrahenta. W polu VAT UE wpisuj kolejno
FI12345671 (format i suma poprawne), FI12345672 (błędna suma), HR69435151530
(format i suma poprawne), BE2123456789 (błędny format), EL123456789 lub
XI123456789 (format bez pełnej kontroli, Unknown). Użyj istniejącego przycisku
**Normalizuj i sprawdź identyfikatory**. To przykłady kontroli lokalnej, nie dane
do potwierdzania istnienia firm ani zapytań do produkcyjnego VIES. Można zamknąć
szkic bez zapisu. Nowej próby rzeczywistego okna Avalonia w tym etapie nie wykonano;
istniejące testy klienta weszły do przebiegu offline.
